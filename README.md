#### Написание парсера, заполняющего инфоблок элементами

Парсер расположен по пути: `site/parser/vacancy_new.php`

Файл для импорта парсером расположен по пути: `site/parser/vacancy.csv`

Для написания парсера учитываем, что в новом инфоблоке есть:
* Поля со значением (строка, число и т.д.), с которыми нужно сделать предобработку и это значение сохранить в свойстве элемента инфоблока;
  * Поля со значением могут быть множественными. Исходя из приложенного файла импорта такими будут: `Требования к соискателю`, `Основные обязанности` и `Условия работы`;
  * В таких полях примем разделителем `•` (знак маркера), будем разбивать значение из импорта по этому разделителю на несколько значений;
* Поля с типом "Список" заполняются другим способом. Нужно по значению из импорта предугадать совпадение одного из предустановленного значения списка и значения из импорта;
  * Если это "Комбинат/Офис", то ищем все варианты свойства, схожие с введенным значением из импорта, а потом выбираем самый подходящий.
  * Если это любой другой, то ищем предустановленное значение, в которое входит текущее рассматриваемое значение из импорта;
  * При нахождении соответствия устанавливаем ИД значения свойства в качестве значения текущего свойства в импорте.

#### Проверка парсера на заполнение значений типа "Список"

Для работы заполнения значений типа "Список":
1) Получаем список всех возможных значений свойств и группируем их по символьному коду свойства;
2) Значения свойства храним как пары ключ-имя и значение-ид значения из API;
3) CSV рассматриваем построчно, формируем массив параметров, в котором сначала записаны значения из строки импорта как есть;
4) Затем для тех значений, что относятся к свойствам списка, меняем значение массива параметра на его ИД-значения (если нет, то пустую строку);
5) А для тех значений, что являются свойствами не типа "Список", делаем обработку и запись как уже упомянуто в пункте "Написание парсера, заполняющего инфоблок элементами".

### Об создании и кастомизации шаблона компонента news.list

Для хранения измененных шаблонов создана папка `/local` (в папке `/site`)

На тестовом сайте используется шаблон `Адаптивный шаблон интернет-магазина`,
его ид=`eshop_bootstrap_v4`

В данном случае по умолчанию шаблоном компонента `news.list` является
шаблон `bootstrap_v4`.

Войдя в аккаунт администратора можно скопировать шаблон в один из существующих шаблонов сайта. В данном случае шаблон (`bootstrap_v4`) скопирован в шаблон `.default`

Получен путь до шаблона компонента такой: `/site/local/templates/.default/components/bitrix/news.list/`

Содержимое папки шаблона (<news.list> - это путь до папки компонента):
* `<news.list>/bootstrap_v4/images/` - папка до картинок компонента
* `<news.list>/bootstrap_v4/lang/` - папка до языковых параметров (переводов) компонента
* `<news.list>/bootstrap_v4/.parameters.php` - получение данных для шаблона (получение списка новостей из инфоблока и других параметров)
* `<news.list>/bootstrap_v4/.result_modifier.php` - подготовка уже полученных данных для шаблона (уточнение параметров элементов списка новостей из инфоблока и других параметров)
* `<news.list>/bootstrap_v4/script.js` - JavaScript функции для дополнительного функционала на стороне клиента
* `<news.list>/bootstrap_v4/style.css` - Стилизация компонента
* `<news.list>/bootstrap_v4/template.php` - Файл шаблона компонента. Данные проходят такой путь: `.parameters.php -> .result_modifier.php -> template.php`
